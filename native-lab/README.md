# GLYPH Native Lab — isolated engineering prototype

Новый самостоятельный проект. Не миграция существующего GLYPH, не реализация
его embedded ABI, не промышленный релиз. Код не подключается к OVH, Google Drive
или документам пользователя. Ничего не удаляет, не меняет настройки процессора.

## Работающий вертикальный срез

Linux/WSL, C++20, RAII. `pack`, `verify`, `restore`, `count` точной бинарной
последовательности (HEX). Потоковая обработка блоками по 1 МиБ: объём буферов
не зависит от размера файла. DEFLATE level 1 либо RAW, если сжатие не уменьшает
блок. SHA-256 каждого блока и всего исходного потока; строгие границы декодера.
Поиск KMP учитывает перекрытия и границы блоков. Результат счётчика выдаётся
только после проверки целого архива. Это линейное сканирование, не FM-индекс.

Выходной файл создаётся временно с правами 0600; успешная публикация не
перезаписывает существующие пути. `fsync(file)`, hard-link publication,
`unlink(temp)`, `fsync(directory)`. При сбое питания до завершения возможен
оставшийся скрытый временный файл. При ошибке fsync каталога опубликованный
файл может существовать, хотя команда вернула ошибку. Его нужно проверить.

```sh
# Зависимости на Debian/Ubuntu (установку выполняет владелец машины):
# g++, make, zlib1g-dev, libssl-dev, python3 (только тесты)
make
make test
make sanitize
./glyph-native pack input.bin archive.gnl
./glyph-native verify archive.gnl
./glyph-native count archive.gnl 414243
./glyph-native restore archive.gnl recovered.bin
```

Исходник должен быть неизменяемым на время операции. Проверка size/mtime/ctime
ловит обычные изменения, но не заменяет filesystem snapshot и не защищает от
привилегированного атакующего. Каталог назначения должен быть доверенным.
Декодер ограничивает размер блока, но не суммарный объём восстановления:
для недоверенного архива обязательны quota/rlimit, изоляция и свободное место.
Хеши обнаруживают повреждение, но НЕ аутентифицируют архив и НЕ исправляют его.

## Чего здесь ещё нет

Версии, CDC/dedup/delta, каталог документов, поиск по датам, UI, LLM, миграция
старых контейнеров, FM-index, подписи, шифрование, ECC repair, сетевой сервер,
backpressure очереди, многопоточность, Windows native, промышленная совместимость.
Нельзя удалять оригиналы на основании этого экспериментального инструмента.
Формат предварительный; совместимость будущих версий не обещана.

## Решения по предложенным аппаратным фильтрам

| Фильтр | Решение этого этапа |
|---|---|
| Компилируемый код, детерминированное освобождение | C++20/RAII; Python только стенд |
| Ограниченная RAM, последовательный доступ | 1 МиБ фиксированные блоки; два переиспользуемых буфера |
| Cache-friendly | Плоские массивы; нет object-per-byte. L1/L2 misses ещё не измерены |
| Размер бинарника | Измеряем release; hard gate <=256 КиБ для данной динамической сборки |
| Статическая линковка | Не включена: размер и обновления библиотек требуют отдельного сравнения |
| SIMD | OpenSSL/zlib могут использовать оптимизации; свой SIMD ещё не добавлен и не измерен |
| mmap/zero-copy | Не включены: декомпрессия требует буферов; mmap изменяемого файла имеет SIGBUS/TOCTOU риски |
| io_uring/epoll | Не нужны для однопоточного offline CLI; кандидат при доказанном I/O bottleneck |
| Huge pages, NUMA, pinning | Не включены без целевых измерений; нет гарантий выигрыш/энергия |
| Lock-free/share-nothing | Нет общих изменяемых данных между потоками: один поток; CAS не нужен |
| Бинарный протокол | Версионированный LE-формат; без сериализации C++ struct/padding |
| Плотность против выравнивания | Диск компактный; отказ от выравнивания RAM не является целью |
| Append-only / LSM | План immutable segments + отдельный транзакционный каталог; LSM не файловая система |
| Физическая геометрия flash | Не известна приложению за FTL; direct I/O не включён |
| Изоляция / микроядро / bare metal | Обычный непривилегированный Linux процесс; своё ядро не строим |
| ECC/самоконтроль | SHA-256 и verify реализованы; исправление требует независимых копий/паритета |
| Внутренняя сеть без криптографии | Не принимать как безопасное умолчание; сеть здесь отсутствует |
| In-memory compute / neuromorphic | Нужна иная аппаратура; не реализуемо программным флагом на ноутбуке |
| Performance governor | Только отдельный разрешённый benchmark, не настройка продукта |
| Отключение thermal throttling | Отвергнуто: защита оборудования остаётся включённой |
| Детерминизм | Повторяемые байты при тех же библиотеках; не обещаем детерминированную задержку |
| Ассемблерный аудит | Отдельный будущий gate горячих функций, не заявление о выполнении |

## Дальше — без подмены измерений обещаниями

1. Сравнить с zstd/LZ4 и исходным GLYPH на одинаковом наборе, включая JPEG/video
   и случайные данные. Текущий zlib выбран как доступный baseline, НЕ как лучший кодек.
2. Immutable content-addressed chunks, ограниченный дисковый индекс, manifest версии:
   одинаковые блоки хранятся один раз. Сначала byte-perfect и crash recovery, потом CDC/SIMD.
3. Независимый импорт/экспорт, UTC saved_at и отдельно provenance дат исходника.
4. Fault injection: ENOSPC, EIO, power loss, concurrent publication, writer mutation;
   fuzzing, 32-bit/ARM, TB-scale, dependency CVE audit. Текущие тесты этого не заменяют.
5. Зафиксировать допустимые RAM/CPU/время/размер на ноутбуке и OVH; измерить energy/J/GB
   только с реальным счётчиком. Не выводить энергопотребление из времени работы.
6. UI preview/search/version/delete с подтверждением и резервной копией.

## Дисковый формат GNLAB v1

8 magic bytes: `47 4e 4c 41 42 00 01 00`.
Каждый блок: u32 raw_length, u32 stored_length, u32 codec (0 RAW, 1 zlib),
32 SHA256 bytes of raw payload, then stored payload. Integers little endian.
Both lengths <=1048576; raw_length >0. Footer: u32 zero, u64 total_raw_length,
32 SHA256 bytes of entire raw input. Exact EOF mandatory. Empty files supported.
No embedded paths, permissions, timestamps or executable metadata.
