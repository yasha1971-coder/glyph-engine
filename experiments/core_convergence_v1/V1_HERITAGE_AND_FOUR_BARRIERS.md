**Do not combine A's verified human trust and B's ratio into a claim that one system already achieved 0.336× full authenticated storage.** Those two experimental results apply to different corpora and nonidentical verification paths.

### Bridge to demonstrate, not assume

\`same committed corpus/generation + same exact query + verified candidate set + same human selection + same materialized object SHA-256 + independently portable replay\`

must hold with **the compact representation** substituted under the original trust laws. It is not sufficient merely to have one successful V1 run and one successful RLB3X run separately.

## 4. Priority experiments and falsifiers

### G-TRUST — Preserve the existing authority semantics

On a pinned, *new publicly redistributable* corpus and fixed query set: run frozen V1 reference where supported, then the compact candidate/adapter. Enforce:
- Phase A no payload materialization; exact candidate identity and corpus/generation binding; human-only choice;
- Phase B never accepts a mismatched receipt/selection or missing cache; decoded result must hash to authentic source;
- missing/corrupt segment, absent source unit, swapped rank/locate sidecar, stale root or incomplete coverage => FAIL/UNTRUSTED/UNKNOWN, not PROVEN_EMPTY;
- version/supersession semantics explicit and unchanged.

**PASS**: independent parity of exact, human-gated selected bytes and fail-closed behavior under a named supported scope, with a portable verifier bundle. **BLOCKED** if the frozen runtime cannot consume this corpus without modifying frozen artifacts: document a versioned adapter and test a subset independently; do not forge a parity claim.

### G-PORTABLE — Reconcile proof costs and portability

Package all mandatory compressed payload/index/locate, provenance, manifests/evidence, decoder/verifier executables and any recovery metadata in an independent replay environment. Measure full bytes and source-code/runtime packaging assumptions. Verify selected object after original source path and original repo are unavailable. First report full-segment reconstruction cost as baseline; only then research authenticated *bounded/partial* verification. Independent external root or witness must be pinned or lack of currentness authority explicitly retained as a limitation.

### G-SCALE — Respect the owner's four critical barriers

1. Corpus scale qualification at ~250MB → 100GB → 1TB → 10TB, with intermediate guardrails if the 100GB jump is too large. Record peak build RAM, open RAM, startup time, query p50/p95/p99, decoded-byte amplification, failure recovery and full storage at EACH level. No automatic extrapolation.
2. Reduce **complete authenticated retained-state** ratio on suitable declared corpora from historical 1.08773 toward the research target **≤0.70×**, including proof/search/recovery overhead and all mandatory runtime artifacts. Do not present ≤0.70× as a universal mathematical promise across encrypted/precompressed data.
3. Move proven bottlenecks toward a stable native implementation *after* independent Embedded I0 second review and explicit ABI freeze decision. “Python → C++” is a delivery/efficiency target, not authorization to rewrite frozen trust logic or bypass executable proof contracts.
4. Go from one demonstrated query to varied real workloads (email, notes, documents, photos and version history). Distinguish exact-byte search from semantic discovery and from OCR/metadata indexing; a media file is not automatically keyword-searchable in its binary representation.

At all steps keep an independent exact corpus oracle and actual source-byte restore; models are optional and never trusted as the source of truth.

### G-TRUST-HISTORY — Real currentness, versions and external witness

Run retained successive commits with real supersession, fork, rollback, pinned generations, expired/corrupt witness and a separate verifier. Adversarial fixtures alone do not establish trustworthy years-long history. A false \`PROVEN_EMPTY\` or a stale version accepted as current is a stop failure.
